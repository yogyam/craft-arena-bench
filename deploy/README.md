# Deploying the public arena server

For the maintainer. One Ubuntu 24.04 machine (Oracle Cloud always-free ARM, 4 cores, 24 GB) runs three things as the unprivileged user `arena`:

| Service | What | Listens on |
|---|---|---|
| `velocity` | The front door: Mojang login, forwards players to the backend | 0.0.0.0:25565 |
| `paper` | The arena world | 127.0.0.1:25566 (players only via Velocity), RCON 127.0.0.1:25575 |
| `arena-harness` | Exhibition and challenge matches, writes `arena/results.json` | nothing public |

## On AWS instead, with OpenTofu or Terraform

`deploy/aws/main.tf` creates the same machine on AWS: a Graviton instance with Ubuntu 24.04, a fixed public address, a security group that admits SSH from one address and Minecraft from anywhere, and a first boot that clones this repository and runs `deploy/bootstrap.sh`. The machine holds no cloud credentials.

```bash
aws configure                         # once, with an access key for a user that may manage EC2
cd deploy/aws && tofu init
tofu apply -var ssh_cidr=$(curl -s https://api.ipify.org)/32
```

Cost: a t4g.small is about 18 dollars a month all-in (instance, disk, public address), a t4g.medium about 31; Hetzner's equivalent is about 4 euros. `budget.tf` adds a monthly spending line (default 30 dollars) with alerts at 80% and 100% and an automatic stop of the instance when actual spend crosses it. AWS evaluates budgets a few times a day, so the stop can lag by hours; restarting afterwards is deliberate (`aws ec2 start-instances`). The IAM user that applies this needs `AmazonEC2FullAccess`, `AWSBudgetsActionsWithAWSResourceControlAccess`, and, for the first apply only, enough IAM access to create the budget's stop role. The state file stays on the machine that ran `tofu apply`; it is ignored by git.

## Steps

1. Create the machine (Ubuntu 24.04, arm64). In Oracle's console open ingress for TCP 25565 from 0.0.0.0/0 on the subnet's security list; SSH is open by default. Nothing else.
2. Copy this folder over and run the bootstrap as root once:

   ```bash
   scp -r deploy ubuntu@<ip>:
   ssh ubuntu@<ip> 'sudo bash deploy/bootstrap.sh'
   ```

   It installs Java 25, creates the `arena` user, downloads and verifies both jars, generates the RCON password and the Velocity forwarding secret into `/opt/arena/secrets/` (mode 600, owner `arena`), writes the configs, enables `ufw` with 22 and 25565 only, and starts the services.
3. Check from your own machine: `mc://<ip>` in a Minecraft client joins and lands in spectator mode. `nc -zv <ip> 25566` is refused.
4. (After stage 7 step 4 exists.) Clone the repository on the machine as `arena` (`/opt/arena/craft-arena-bench`), `pip install .` into a venv, `npm ci` in `body/`, then `systemctl enable --now arena-harness`.

## Oracle quirks

- Always-free ARM capacity comes and goes. If instance creation fails with "Out of host capacity", try another availability domain or try again later; it is not a quota problem.
- Oracle's Ubuntu images carry iptables rules that reject every port but 22, separate from the cloud security list. The bootstrap removes them and lets `ufw` be the only host firewall.
- Always-free resources must be in the account's home region, chosen at sign-up and fixed afterwards.

## Secrets

Two, both generated by the bootstrap and never leaving the machine: `/opt/arena/secrets/rcon_password` and `/opt/arena/secrets/forwarding.secret`. Rotate by deleting them and re-running the bootstrap's secrets step; the configs are regenerated from them.

## Updating

`sudo bash deploy/bootstrap.sh` is idempotent: re-run it after bumping the pinned builds in this folder and in `src/craft_arena_bench/__init__.py`.
